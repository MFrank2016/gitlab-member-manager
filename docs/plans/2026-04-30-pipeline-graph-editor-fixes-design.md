# 流程图编辑页面问题修复设计
日期：2026-04-30  
状态：已确认（brainstorming）

## 1. 背景

当前流程图编辑页已经切到基于 `@xyflow/react` 的阶段感知 DAG 编辑器，但实际可用性仍然不达标。用户当前明确反馈了 6 个问题：

- 编辑操作列表里，按钮宽度超出边框
- 画布无法拖拽
- 阶段或步骤无法点击
- 目前新建流水线无法继续，只能点击添加阶段和适配全貌按钮，创建流程无法顺利进行
- 画布上显示的动作节点无法展示全貌
- 画布无法缩放

代码排查后，现状存在以下结构性偏差：

- `PipelineGraphEditor.tsx` 左侧栏使用固定窄列，按钮组件默认单行显示，长中文文案容易溢出
- 画布使用了 `@xyflow/react`，但入口代码未引入官方样式，基础交互命中层行为偏离官方预期
- `createEmptyPipelineDraft()` 默认会创建 1 个阶段和 1 个动作节点，这与“新建时默认只有阶段”的目标交互冲突
- `toDraftFromDetail()` 在明细没有节点时也会自动补 1 个节点，导致编辑器不忠实反映持久化数据
- 画布节点当前同时承载结构识别和过多信息展示，没有明确区分“画布摘要视图”和“右侧详细属性面板”

本次修复目标不是重写流程系统，也不是引入新的后端语义，而是在保持现有草稿模型、后端接口和阶段感知 DAG 模型不变的前提下，把编辑器修到可顺畅创建、可导航、可选择、可保存的状态。

## 2. 用户确认的交互约束

本次设计以用户已确认的交互要求为准：

- 采用标准流程图模式：空白处拖动画布，滚轮缩放，单击阶段或节点选中，动作节点允许拖动，阶段容器固定不移动
- 新建流水线默认有 1 个阶段、0 个动作节点
- 打开新建流水线时，默认阶段自动选中
- 点击“在所选阶段添加节点”后，新节点要落在当前阶段内的安全位置，并且默认完整可见
- 画布上的节点只展示名称和简要信息，详细参数继续放右侧属性面板
- 保存前仍然要求定义完整，但编辑过程中允许处于“阶段存在但尚未添加节点”的中间态

## 3. 目标与非目标

### 3.1 目标

- 一次性修复上述 6 个交互与布局问题
- 保持 `PipelineDraft` 作为唯一事实来源，不再引入第二套持久图状态
- 让“新建流水线”路径从进入页面开始即可持续完成：填名称、添加节点、编辑节点、连线、保存
- 让画布承担结构与依赖关系展示，让右侧面板承担详细属性编辑
- 保持当前后端 payload、持久化模型、阶段/节点/连线语义不变

### 3.2 非目标

- 不修改后端 schema、Tauri 命令或运行时执行语义
- 不引入自动保存
- 不支持阶段自由拖动或任意二维布局
- 不将阶段容器重构为全新泳道系统
- 不在画布节点上展示完整参数表单或大段 JSON

## 4. 核心设计

### 4.1 `PipelineDraft` 继续作为唯一事实来源

编辑器继续沿用当前模型：

- `draft` 保存名称、变量、阶段、节点、连线和调度
- `graphState` 仅由 `draft` 派生
- 画布本地状态只保存临时 UI 信息：
  - `selectedId`
  - `connectionTarget`
  - `graphMessage`
  - React Flow 视口控制引用

这样可以保证：

- 节点拖拽后的位置直接写回草稿，不会在切页或保存时丢失
- 新建、编辑、删除、保存始终基于同一份数据
- 测试可以直接断言草稿和 payload，而不是追踪多份同步状态

### 4.2 初始化与选择规则重置

`createEmptyPipelineDraft()` 改为：

- 默认创建 1 个阶段
- 默认不创建动作节点
- 默认没有连线
- 默认变量行根据空节点集推导，不制造伪变量

编辑器选择规则改为：

- 新建模式进入画布时，自动选中第一个阶段
- 编辑模式进入画布时，有节点则优先选中第一个节点；无节点则选中第一个阶段
- 删除当前节点后，优先回退到其所属阶段
- 删除当前阶段后，回退到剩余第一个阶段；无阶段则清空选中
- 点击空白画布时清空选中

这套规则直接解决“新建页无法继续”的问题，并避免删除后进入僵死状态。

### 4.3 画布导航恢复为基础能力

画布必须稳定支持以下能力：

- 空白处拖动画布
- 滚轮缩放
- `Controls`
- `MiniMap`
- “适配全貌”显式按钮

为此需要在前端入口补齐 `@xyflow/react` 官方样式，并对自定义节点的命中区和布局进行校正，确保缩放、拖拽和点击行为与 React Flow 预期一致。

阶段容器仍保持固定位置，不允许拖动；动作节点允许在所属阶段容器内拖动，并将拖拽后的 `position` 立即写回 `draft`。

### 4.4 三栏布局和左侧操作栏修正

画布页继续维持三栏结构，但布局策略改为“画布优先、左侧防溢出、右侧固定可读”：

- 左栏宽度提升，允许中文按钮文案自然换行
- 中栏保留足够最小宽度，优先保证画布可操作
- 右栏保持固定属性编辑宽度

左侧按钮统一改为整列铺满容器宽度，文案允许换行或自适应高度，不再依赖单行 `whitespace-nowrap` 展示。

这部分将直接解决按钮溢出边框的问题。

### 4.5 阶段容器和节点卡片改为“结构摘要视图”

阶段容器不再追求紧凑卡片感，而是承担稳定结构槽位：

- 足够容纳多个节点
- 留出画布空白用于导航和节点排布
- 固定顺序，不承载复杂编辑操作

动作节点只展示摘要信息：

- 节点名称
- 节点类型标签
- 所属阶段或少量关键提示
- 启用/禁用状态

详细参数、JSON、字段级编辑全部保留在右侧 `PipelineGraphSelectionPanel`。

节点卡片宽高基线会提升，但不会为了展示所有参数而无限放大。超长内容通过换行和摘要裁剪控制，避免画布节点撑坏整体布局。

### 4.6 新增节点的安全落点与可见性保证

新增节点时，不再仅使用固定公式粗放堆叠，而是按当前阶段内已有节点数量和容器可用区域计算安全落点，保证：

- 不与已有节点重叠
- 不贴边
- 不超出阶段容器
- 新节点创建后自动成为当前选中对象
- 如当前视口不足以完整显示新节点，则进行一次轻量视角修正

这样用户打开新建页后，可以直接：

- 填流水线名称
- 点击“在所选阶段添加节点”
- 立刻在右侧编辑该节点属性

### 4.7 校验与保存分层

本次修复继续保留“保存前必须完整”的约束，但将“编辑中间态”和“保存校验失败”分离：

- 编辑中允许存在“阶段有了，但节点尚未添加”的状态
- 点击保存或校验时，才统一检查：
  - 流水线名称不能为空
  - 至少存在 1 个阶段
  - 每个阶段至少有 1 个节点
  - 节点类型不能为空
  - 连线不能重复、回环或逆阶段回连
  - payload 构建必须成功

错误反馈继续保持中文优先：

- 左侧或顶部给出简洁提示
- 校验摘要列出阻塞问题
- 右侧属性面板继续承载对象级编辑

## 6. 验收标准

修复完成后，至少要满足以下可见结果：

- 左侧长按钮文案不再溢出边框
- 空白处可以拖动画布
- 滚轮可以缩放画布
- 阶段和节点都能稳定点击选中
- 新建流水线进入后，默认阶段已选中，可以立即添加节点
- 新节点创建后完整可见，并自动切到右侧节点属性面板
- 画布节点只展示名称和简要信息，详细参数仍在右侧编辑
- “适配全貌”仍然可用，`MiniMap` 和 `Controls` 保持可见
- 保存前校验继续阻止不完整定义，但不再阻塞正常编辑起步路径

## 7. 结论

这次修复的重点不是再加功能，而是把当前流程图编辑器从“有图形外壳但核心交互不可用”修成“默认路径可继续、画布可导航、对象可编辑、保存可验证”的状态。

最终方案概括为：

- 修正默认草稿和选择规则
- 恢复 React Flow 基础导航能力
- 调整三栏布局与左侧操作栏
- 将节点显示收敛为摘要视图
- 保持现有后端和草稿模型不变
