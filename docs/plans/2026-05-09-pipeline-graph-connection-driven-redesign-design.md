# 流程图连接驱动重构设计

日期：2026-05-09
状态：已确认（brainstorming）

## 1. 背景

当前流程图编辑器已经完成了第一阶段的交互增强：稳定选中、右键菜单、校验式建点、阶段内网格布局、阶段排序与节点重排。但这套模型的主前提仍然是“先选阶段，再把节点塞进阶段”，与当前真实目标存在根本偏差：

- 用户希望沿着节点持续往后搭流程，而不是先想清楚阶段容器。
- 用户希望拖拽表达结构意图，而不是手动维护像素坐标。
- 用户希望节点能跨阶段拖放，并由系统自动修正阶段归属与阶段顺序。
- 用户希望新增后继节点时，系统自动整理局部分叉结构，而不是继续要求手动摆点。

因此，这次不是继续给现有 v1 交互补丁，而是把流程图重构为“连接驱动创建 + 自动布局 + 结构吸附拖拽 + 依赖驱动阶段重排”的新主流程。

## 2. 与现有 v1 方案的关系

仓库内现有的 OpenSpec 变更 `update-pipeline-graph-canvas-interactions` 主要覆盖：

- 稳定选中
- 阶段/节点右键菜单
- 阶段作用域的创建对话框
- 阶段内网格布局
- 阶段横向排序
- 节点仅允许在当前阶段内拖拽

本设计明确超出该 v1 范围，新增或改变的核心点包括：

- 新建节点只能通过节点后的连接点触发
- 空阶段通过起始锚点进入首个节点创建流程
- 节点拖拽允许跨阶段
- 阶段顺序不再主要由手工维护，而由跨阶段依赖稳定拓扑重排
- 阶段内布局从“栅格槽位”升级为“连接驱动的分层自动布局”

后续实现计划需要明确：是扩展当前 OpenSpec 变更，还是另起一次新的二阶段变更。

## 3. 目标与非目标

### 3.1 目标

- 把节点右侧输出连接点改为唯一主创建入口。
- 支持空阶段起图，但仍保持“只能通过连接点创建节点”的交互主轴。
- 让所有节点保持统一尺寸，画布上只展示节点类型与节点名称。
- 让同一父节点的多个直接后继在右侧纵向堆叠。
- 让父节点始终对齐其后继组的垂直中线。
- 让阶段内内容在阶段容器中保持水平居中与垂直居中。
- 让拖拽表达结构重排意图，而不是保留自由像素坐标。
- 支持节点跨阶段拖放，并自动修正阶段归属与全局阶段顺序。
- 保证最终结果始终是合法 DAG；能自动修复则自动修复，不能修复则明确回退并提示中文原因。

### 3.2 非目标

- 不替换 React Flow。
- 不移除 `PipelineDraft`、阶段、节点、边这套持久化主模型。
- 不在本次重构中改造运行时调度语义。
- 不在本次重构中引入批量选择、批量编辑或自由画布模式。
- 不在本次重构中实现完全自动推导阶段并取消手工阶段配置能力。

## 4. 核心交互模型

### 4.1 创建入口

新建节点只能通过以下两类连接点触发：

- 动作节点右侧输出连接点
- 空阶段中央起始锚点的右侧输出连接点

以下入口退出主流程：

- 左侧“在所选阶段添加节点”按钮
- 阶段右键菜单中的“添加节点”动作

如果保留上述旧入口，也只能作为迁移期兼容入口，并最终复用同一套“连接点触发创建”的流程，不允许出现两套不同的创建语义。

### 4.2 创建流程

点击输出连接点后，编辑器进入“待创建后继节点”状态：

1. 显示临时预览连线。
2. 在源节点附近打开轻量创建面板。
3. 用户选择节点类型并填写最少必要字段。
4. 确认后自动创建节点、创建连线、局部重排、切换到新节点编辑态。
5. 取消后不落图、不保留预览边、不污染草稿。

### 4.3 空阶段起图

空阶段中心展示一个非持久化“起始锚点”：

- 它不是业务节点，不参与运行时。
- 它只承担第一个节点的创建入口。
- 通过起始锚点右侧输出连接点创建首个节点。

这样既能让空阶段可用，又不会破坏“节点只能从连接点创建”的总规则。

## 5. 画布节点与视觉模型

### 5.1 节点卡片

所有动作节点采用统一宽高，保持一致视觉节奏，避免布局抖动。

画布卡片只保留：

- 节点类型
- 节点名称

不在卡片中展示：

- 参数摘要
- 变量摘要
- 复杂状态文案
- 长说明文本

这些信息统一收敛到右侧编辑区或创建面板。

### 5.2 阶段容器

阶段容器继续存在，但定位从“用户先操作的对象”降级为“系统用于分组、排序和承载布局的容器”。

阶段容器需要满足：

- 保持最小宽高
- 随内容包围盒自适应增长
- 内部内容始终水平居中
- 内部内容始终垂直居中

因此，阶段内图形不再贴左上角堆积，而是始终保持稳定、居中的视觉重心。

## 6. 自动布局规则

### 6.1 布局范式

阶段内布局从“自由坐标 + 栅格重排”调整为“连接驱动的分层自动布局”：

- 父节点在左，直接后继在右
- 同层节点纵向堆叠
- 多个直接后继统一在右侧上下展开
- 父节点的垂直中心对齐后继组整体中线

这个规则递归应用到受影响的局部子图。

### 6.2 单后继

从节点 `A` 创建第一个后继 `B` 时：

- `B` 放在 `A` 右侧
- `A` 与 `B` 保持同一水平线

### 6.3 多后继

如果节点 `A` 已有一个直接后继 `B`，再从 `A` 新增直接后继 `C`：

- `B` 与 `C` 在 `A` 右侧纵向堆叠
- `B` 在上，`C` 在下
- `A` 自动移动到 `B/C` 组的垂直中线位置

目标形态是：

```text
A      B
 \
  \
   C
```

更准确地说：

- `A` 在左列
- `B/C` 在右列
- `B/C` 纵向排列
- `A` 的中心点与 `B/C` 组中心线对齐

### 6.4 局部重排

新增后继节点时，系统触发的是局部重排，而不是整图无差别重排。

受影响的最小范围包括：

- 源节点
- 源节点的直接后继组
- 与该后继组布局直接相关的局部子图

无关阶段与无关子图不应因为一次新增后继而无意义跳动。

### 6.5 阶段内双轴居中

每次局部布局完成后，系统都要：

1. 计算当前阶段内容包围盒。
2. 根据最小尺寸与内容尺寸确定阶段容器大小。
3. 将内容块在容器内部做水平居中。
4. 将内容块在容器内部做垂直居中。

这条规则适用于：

- 新增节点
- 删除节点
- 节点拖拽重排
- 节点跨阶段迁移

## 7. 拖拽与吸附语义

### 7.1 拖拽语义变更

拖拽不再表达“保留这个像素坐标”，而表达“我想把节点调整到这个结构位置附近”。

因此鼠标释放后：

- 系统不保留原始落点坐标
- 系统寻找最近的合法吸附位
- 系统基于吸附位重建局部布局
- 节点最终回到规则化、整齐的位置

### 7.2 最近位置的判定

“最近位置”按以下优先级解释：

1. 最近的合法目标阶段
2. 目标阶段内最近的结构列
3. 该列中最近的纵向插入位置
4. 若落在某节点的后继区，则理解为“想挂到该节点后面”
5. 若落在某后继组内部，则理解为“想调整兄弟顺序”

### 7.3 吸附后的自动整理

吸附成功后系统立即：

- 修正该节点所在兄弟组顺序
- 重新对齐父节点到后继组中线
- 重算局部布局
- 将阶段内容重新做双轴居中

因此，拖拽后的结果必须始终整齐，不允许留下半自由、半规则化的中间状态。

## 8. 阶段归属与阶段顺序

### 8.1 默认阶段归属

从节点 `A` 创建后继节点 `B` 时：

- `B` 默认继承 `A` 的 `stageKey`
- 即默认先放在同阶段

创建动作默认保守，不主动跨阶段。

### 8.2 跨阶段拖放

节点允许跨阶段拖放。

拖放后目标阶段判定规则：

- 优先看节点中心点最终落入的阶段框
- 若落在边界模糊区，则按距离最近的阶段内容中心决定归属

一旦跨阶段成功：

- 节点 `stageKey` 立即更新
- 原阶段触发局部重排
- 目标阶段触发局部重排

节点的业务内容、参数、标识不变，只修改结构位置和归属阶段。

### 8.3 阶段顺序自动推导

阶段左右顺序不再主要依赖手工维护，而是由跨阶段依赖关系驱动的稳定拓扑排序自动推导。

排序规则：

1. 先从跨阶段边提取阶段依赖。
2. 再根据阶段依赖做稳定拓扑排序。
3. 满足依赖方向优先。
4. 在无依赖冲突处尽量保持原有相对顺序。

这能保证：

- 阶段顺序与节点依赖一致
- 无关阶段不被频繁打散
- 用户无需手工反复整理阶段左右位置

### 8.4 空阶段

空阶段默认保留，不自动删除。

原因：

- 阶段可能仍有名称、开关或后续待补节点配置。
- 拖走或删除最后一个节点时，不应顺带丢失阶段。
- 空阶段仍可通过起始锚点继续建图。

## 9. 无解结构与回退规则

系统默认原则是：优先自动修复，不向用户暴露脏结构。

处理顺序：

1. 尝试调整节点归属。
2. 尝试重排阶段顺序。
3. 如果仍无法形成合法 DAG，则回退本次操作。

典型回退提示：

- `当前拖放会形成循环依赖，已撤销本次调整。`
- `当前节点不能放入该阶段，否则阶段顺序无法保持合法。`

禁止的结果是：静默保留一个半合法、半非法的图，要求用户自行补救。

## 10. 删除与空态回退

- 删除节点后，需要同步删除相关边，并触发局部重排。
- 删除后如果父节点失去全部直接后继，则父节点回到普通可继续扩展状态。
- 删除阶段最后一个节点时，阶段本身保留为空阶段。
- 删除后阶段或节点选择失效时，编辑器需稳定回退到最近有效对象或空状态。

## 12. 验收重点

这次重构的验收重点不是某个按钮是否可点，而是下面三条主路径是否顺畅、稳定、可重建：

1. 从空阶段开始，通过起始锚点和连接点持续往后搭流程。
2. 从某节点继续新增后继时，系统按“右侧纵向分叉 + 父节点居中 + 阶段内双轴居中”自动整理布局。
3. 节点跨阶段拖放后，系统自动改阶段归属、自动重排阶段顺序，并仍然得到合法 DAG。

## 13. 总结

这次重构不再继续修补“阶段优先、阶段内半手动摆放”的旧主流程，而是明确切换为：

- 连接驱动创建
- 自动布局
- 结构吸附拖拽
- 依赖驱动阶段重排

在保留现有 `PipelineDraft`、React Flow 与阶段模型的前提下，这是最贴近当前真实使用路径、且最有机会把流程图真正变得顺手的一条路线。
