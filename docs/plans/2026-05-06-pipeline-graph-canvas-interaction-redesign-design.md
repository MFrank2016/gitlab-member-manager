# 流水线流程图画布交互重构设计

日期：2026-05-06  
状态：已确认（brainstorming）

## 1. 背景

当前“新建流水线定义”的流程图画布已经基于 `@xyflow/react` 实现了阶段容器与动作节点的父子关系，但交互层仍然偏弱：

- 点击阶段没有稳定进入选中与编辑态
- 点击动作节点没有稳定进入选中与编辑态
- 阶段与节点缺少就地右键操作
- 节点新增时只做简单纵向堆叠，无法支持同一阶段内上下左右排列
- 阶段容器尺寸固定，节点变多后易出现拥挤、遮盖与连线空间不足
- 阶段不能拖拽排序，节点拖拽后的布局也缺少可预测的重排规则

这次改造不是重写编辑器，而是在保留现有 `PipelineDraft`、React Flow 和右侧属性面板结构的前提下，把画布提升到“可选中、可右键、可创建、可拖拽、可重排、可保存”的状态。

## 2. 已确认的交互约束

- 阶段内采用栅格/槽位布局。
- 同一阶段内节点支持上下左右排列。
- 节点之间必须保留足够留白，便于连线。
- 阶段容器宽高同时自适应，不再是固定大小。
- 阶段支持左右拖拽排序，但不支持自由摆放。
- 左键点击阶段后，右侧属性面板进入阶段编辑态。
- 右键点击阶段后，弹出菜单：`添加节点`、`删除阶段`。
- 右键阶段里的 `添加节点` 使用对话框，不用二级菜单或小浮层。
- 对话框内可直接设置节点变量、参数等信息。
- 新建节点时，关键字段必须填完才能创建。
- 左键点击节点后，右侧属性面板进入节点编辑态。
- 右键点击节点后，弹出菜单：`删除节点`。
- 节点拖拽到已占用槽位时，当前阶段内自动整体重排。
- 删除阶段时采用级联删除，并在执行前弹确认框。

## 3. 方案选择

已选方案：**在现有 React Flow 父子节点模型上增强交互**。

原因：

- 当前 `stage-group` 父节点 + 动作子节点的结构已经成形，适合继续扩展。
- 右侧 `PipelineGraphSelectionPanel` 已具备承接阶段/节点属性编辑的基础，不需要重造编辑面板。
- 现有 `PipelineDraft` 已经是单一数据源，继续沿用能降低状态分裂风险。
- 与重写布局引擎相比，这条路线更适合在当前仓库中做渐进式增强，并能用现有测试体系兜底。

## 4. 核心设计

### 4.1 数据模型与 UI 状态分层

`PipelineDraft` 继续作为唯一真实数据源，负责持久化：

- `stages`
- `nodes`
- `edges`
- `variableRows`

画布内部新增但不持久化的 UI 状态包括：

- `selectedObject`
- `contextMenuState`
- `createNodeDialogState`
- `activeStageKey`

原则：

- 左键只改变选中态。
- 右键只打开上下文菜单，不直接修改草稿。
- 新建节点对话框只有在校验通过时才真正写入 `PipelineDraft`。
- 节点拖拽和阶段排序最终都回写为 `PipelineDraft` 可重建的结构化结果，而不是依赖临时像素状态。

### 4.2 左键 / 右键交互模型

#### 阶段

- 左键点击阶段：
  - 阶段进入选中态
  - 右侧属性面板切换到阶段属性
  - 更新 `activeStageKey`
- 右键点击阶段：
  - 打开阶段上下文菜单
  - 菜单项：`添加节点`、`删除阶段`

#### 节点

- 左键点击节点：
  - 节点进入选中态
  - 右侧属性面板切换到节点属性
  - `activeStageKey` 同步到该节点所属阶段
- 右键点击节点：
  - 打开节点上下文菜单
  - 菜单项：`删除节点`

#### 空白区域

- 清空显式选中态
- 保留最近的 `activeStageKey`
- 右侧属性面板显示空状态或说明态

### 4.3 新建节点对话框

节点创建不再通过固定的左侧按钮直接塞入默认 `checkout_branch` 节点，而是改为：

1. 右键阶段
2. 选择 `添加节点`
3. 打开“新建节点对话框”

对话框职责：

- 固定当前 `stageKey`
- 选择节点类型
- 渲染对应节点类型的关键字段、变量、参数输入
- 在创建前执行严格校验

校验规则：

- 未选择节点类型不能创建
- 该节点类型的关键字段未填完不能创建
- 参数格式错误不能创建

创建成功后：

- 节点进入当前阶段内部布局算法
- 新节点成为当前选中对象
- 右侧属性面板自动切换到该节点

创建失败时：

- 错误留在对话框内展示
- 不落图
- 不污染现有草稿

### 4.4 阶段容器布局

阶段容器仍保持横向一排，但支持拖拽排序：

- 用户可左右拖拽阶段
- 放下后阶段吸附回统一横向基线
- 实际持久化的是 `draft.stages` 顺序，而不是自由位置

阶段容器大小由内容驱动，宽高同时自适应：

- 标题区高度
- 内部网格列数
- 内部网格行数
- 节点卡片尺寸
- 水平 / 垂直间距
- 容器内边距

这样阶段少节点时不会空得夸张，节点增多时也不会把卡片压扁或挤叠。

### 4.5 阶段内节点栅格布局

节点采用**二维栅格槽位**，不是自由像素布局。

规则：

- 节点在当前阶段内占据一个槽位
- 默认填充顺序为从左到右、从上到下
- 节点卡片之间始终保留固定间距，用于连线穿行
- 节点只能在当前阶段内拖拽，不支持直接跨阶段拖入

布局目标：

- 不重叠
- 不越出阶段容器
- 节点卡片之间保留连线通道
- 节点标题与摘要在卡片内保持完整可读

### 4.6 拖拽与自动整体重排

#### 节点拖拽

- 拖拽时只允许在当前阶段容器内移动
- 落点先映射到最近槽位
- 如果槽位已占用，则触发**当前阶段内整体重排**

整体重排规则：

- 把被拖拽节点视为新的目标位置锚点
- 重新计算当前阶段内所有节点的槽位分布
- 不影响其他阶段
- 不改变节点业务内容，只改变阶段内显示顺序与坐标

用户感知上应表现为：

- 我把节点拖到某个位置
- 系统帮我把这一阶段重新排整齐

#### 阶段拖拽

- 阶段只能做顺序调整
- 不支持垂直乱放或二维自由摆动
- 放下后重新计算全局阶段横向坐标

### 4.7 删除规则

#### 删除节点

- 删除节点本身
- 删除相关连线
- 重新推导变量依赖
- 若当前选中对象失效，回退到最近有效对象或空状态

#### 删除阶段

- 必须先弹确认框
- 确认后级联删除：
  - 该阶段本身
  - 阶段内所有节点
  - 节点相关连线
- 删除后重算阶段顺序与选中态

### 4.8 校验与保存边界

本次改造仍保留“保存前必须完整”的约束，但区分：

- **编辑中间态**
- **保存时阻断态**

允许的编辑中间态：

- 阶段已存在但尚未添加节点
- 节点尚未创建前处于对话框编辑状态

保存时必须检查：

- 流水线名称不为空
- 至少有一个阶段
- 每个阶段至少有一个节点
- 节点类型与关键字段完整
- 连线合法且不形成回环

## 6. 测试策略

必须补的测试包括：

- `graph-model` 单测：
  - 槽位分配
  - 自动重排
  - 阶段容器尺寸计算
  - 阶段排序后的坐标重算
- `PipelineGraphEditor` 组件测试：
  - 左键选中
  - 右键菜单
  - 新建节点对话框
  - 删除节点 / 阶段
  - 节点拖拽重排
  - 阶段拖拽排序
- 页面级 smoke 测试：
  - 在“新建流水线定义”页面中通过画布右键创建节点并保存

## 7. V1 边界

本次明确不做：

- 节点跨阶段拖拽
- 阶段自由摆放
- 多选后的批量菜单
- 自动避线算法
- 触屏手势专门适配

## 8. 结论

这次重构的核心不是堆新功能，而是把流程图画布从“有结构但交互不顺”提升到：

- 左键稳定选中并编辑
- 右键就地操作
- 对话框严格创建节点
- 阶段内二维布局
- 拖拽后自动重排
- 阶段宽高随内容自适应

在保留现有 `PipelineDraft` 和 React Flow 父子节点结构的前提下，这个方案能在控制回归风险的同时，显著提升新建流水线定义的画布可用性。
