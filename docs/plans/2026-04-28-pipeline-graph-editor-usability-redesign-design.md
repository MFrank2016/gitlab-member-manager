# 流程图编排编辑器可用性重构设计

日期：2026-04-28  
状态：已确认（brainstorming 定稿）

## 1. 背景

当前流程定义编辑能力已经从线性节点表单升级到了基于 `@xyflow/react` 的流程图编辑器，但实际体验仍然不可用：

- `WorkflowsPagePipeline.tsx` 同时承载列表、创建弹窗、编辑弹窗和运行弹窗，页面职责过于混杂
- `PipelineDraftForm.tsx` 把基础信息、变量、流程图、调度全部串在同一个长表单里，画布被表单结构挤压
- `PipelineGraphEditor.tsx` 仅实现了最基础的阶段/节点/连线编辑，缺少自由平移、缩放、全貌导航等基础图交互
- 阶段容器和节点卡片信息密度不足，难以快速识别结构关系
- 当前测试只覆盖了增删节点和连线等最小行为，没有覆盖真正的画布可用性

用户反馈集中在四个问题上：

- 页面结构混乱
- 无法自由拖动
- 无法放大缩小
- 看不到全貌

本次改造目标不是重写流程系统，也不是引入新的后端执行语义，而是把现有前端编辑器重构成真正可用的专业编辑态。

## 2. 目标与非目标

### 2.1 目标

- 将流程定义编辑从普通弹窗切换为 `workflows` 标签页内的全屏编辑态
- 保留现有 `@xyflow/react` 技术路线，补齐基础专业交互
- 让阶段固定横向排布，节点在阶段内自由拖动
- 将全局配置与当前对象属性分离，降低编辑认知负担
- 提供清晰的校验、错误定位和未保存保护

### 2.2 非目标

- 不改全局导航架构，不引入新的路由系统
- 不重构后端数据模型或执行器语义
- 不做自动保存
- 不支持阶段自由拖拽到任意位置
- 不引入复杂的左侧节点素材库

## 3. 核心决策

### 3.1 在 `workflows` 页内引入全屏编辑态，而不是继续使用弹窗

`WorkflowsPagePipeline.tsx` 将从“列表页 + 创建弹窗 + 编辑弹窗”改为“列表态 + 全屏编辑态 + 运行弹窗”。

原因：

- 当前应用没有基于路由的页面架构，直接新开路由会把任务扩大为导航重构
- 全屏编辑态能获得足够画布空间，同时保留现有标签页切换模型
- 运行弹窗是瞬时操作，保留弹窗更合理；编辑器是主工作区，不适合继续塞在普通弹窗里

### 3.2 阶段固定横向排布，只允许调整顺序

阶段继续作为执行语义边界，采用稳定的横向泳道布局，从左到右表示阶段顺序。

原因：

- 阶段顺序直接影响用户对执行顺序的理解
- 自由拖动阶段会让视觉语义和执行语义脱节
- 当前数据模型已经更适合维护顺序而不是自由坐标

### 3.3 节点在所属阶段内自由拖动，跨阶段移动使用显式操作

节点可以在阶段内自由拖动并持久化位置；跨阶段移动通过属性面板或明确的“移动到阶段”操作完成，而不是直接拖出容器。

原因：

- 阶段内自由拖动是图编辑器的基础能力
- 直接跨阶段拖拽更容易造成越界和误操作
- 显式跨阶段操作更利于保持 `draft` 单一数据源的一致性

### 3.4 全局配置与当前选中对象属性分离

编辑器采用混合式信息架构：

- 顶部页签承载全局配置：`画布`、`变量`、`调度`、`基础信息`
- 右侧属性面板只展示当前选中阶段或节点的属性

原因：

- 画布需要成为编辑器主角，而不是被全局表单淹没
- 变量、调度、基础信息属于低频全局配置，不应长期占用画布工作面
- 右侧面板只处理当前对象，能显著降低面板复杂度

### 3.5 继续使用 `React Flow`，但补齐完整基础交互

本次不更换图编辑技术路线，继续在 `PipelineGraphEditor.tsx` 中使用 `@xyflow/react`，但补齐以下能力：

- 画布平移
- 滚轮缩放
- 一键适配全貌
- `MiniMap`
- 基础控件面板
- 框选
- 删除选中对象

原因：

- 现有项目已经接入该库，技术成本最低
- 当前问题是“没有把库用完整”，不是库本身不适合

## 4. 编辑器信息架构

### 4.1 页面状态

`WorkflowsPagePipeline.tsx` 收敛为三种主要视图状态：

- `idle`：列表态
- `creating`：新建流程编辑态
- `editing`：编辑已有流程编辑态

运行入口继续保留现有运行弹窗逻辑。

### 4.2 编辑器外壳

新增全屏编辑器外壳组件（建议命名为 `PipelineDefinitionEditorShell`），负责：

- 顶部工具栏
- 顶部页签
- 画布工作区三栏布局
- 未保存离开保护
- 保存 / 校验 / 布局类动作入口

### 4.3 顶部工具栏

顶部工具栏分为两侧：

- 左侧：`返回列表`、当前流程名称、编辑状态提示
- 右侧：`保存`、`校验`、`适配全貌`、`自动整理`

`保存` 与 `校验` 分离，避免用户混淆“结构错误”和“尚未保存”。

### 4.4 顶部页签

顶部页签固定为：

- `画布`
- `变量`
- `调度`
- `基础信息`

默认进入 `画布` 页签。

### 4.5 画布页签三栏布局

画布页签内部采用三栏布局：

- 左侧：轻量结构操作区
- 中间：主画布
- 右侧：当前选中对象属性面板

左侧只保留高频结构操作，例如：

- 添加阶段
- 添加节点
- 删除选中对象
- 阶段数量 / 节点数量摘要

右侧面板行为：

- 选中阶段：显示阶段名称、启用状态、顺序调整入口
- 选中节点：显示节点类型、所属阶段、启用状态、参数配置
- 未选中：显示简要使用引导和当前流程摘要

## 5. 画布交互规范

### 5.1 阶段交互

- 阶段固定横向泳道布局
- 不支持自由拖动阶段位置
- 支持通过明确操作调整阶段顺序
- 第一版优先保证稳定可读，不强求阶段宽度自定义

### 5.2 节点交互

- 每个节点必须归属于一个阶段
- 节点可在所属阶段内自由拖动
- 节点位置变更后需写回 `draft`
- 跨阶段移动通过显式属性操作完成

### 5.3 画布导航

编辑器必须具备以下基础导航能力：

- 拖动画布平移
- 滚轮缩放
- 一键适配全貌
- 右下角基础控件
- `MiniMap`

这些能力的目标是确保用户在流程图变大后，仍然能快速恢复方向感。

### 5.4 选择与连线

- 支持单选阶段 / 节点
- 支持框选多个节点
- 第一版多选不做复杂批量编辑
- 连线只允许发生在动作节点之间
- 禁止自连、重复连线、成环
- 禁止从后序阶段回连前序阶段
- 连线失败时直接展示中文原因

### 5.5 自动整理策略

提供“自动整理布局”入口，但仅在用户主动触发时执行，不做持续自动布局。

原因：

- 自动布局应当是辅助工具，而不是持续覆盖用户手动位置的强制行为

## 6. 状态、校验与错误反馈

### 6.1 编辑器状态

编辑器至少需要可见区分以下状态：

- 未修改
- 有未保存修改
- 校验中
- 保存中
- 保存失败

状态需要在顶部工具栏显式可见，而不是只体现在按钮 loading。

### 6.2 未保存保护

在全屏编辑态下，如果存在未保存修改，点击返回列表时必须二次确认。

确认文案：

`当前有未保存修改，离开后将丢失，是否继续？`

### 6.3 校验分层

交互校验：

- 连线时阻止自环、重复边、非法回连
- 阶段/节点选择时阻止明显越界操作

保存前完整校验：

- 流程名称不能为空
- 至少存在一个阶段
- 阶段存在但没有节点时给出结构提示
- 节点类型和必填参数完整
- 整体无环
- 变量引用合法

### 6.4 错误展示层次

错误展示分为三级：

- 对象级错误：节点或阶段卡片上的错误标记
- 页面级错误摘要：集中列出校验问题，便于定位
- 操作级 toast：仅提示动作结果，不承载全部细节

所有用户可见错误默认中文输出。

### 6.5 保存策略

第一版采用显式保存，不做自动保存。

原因：

- 流程图编辑是结构性操作，自动保存会把半成品写入持久层
- 当前更需要可控、可验证的编辑体验

## 9. 验收标准

本次改造完成后，需要满足以下可见结果：

- 点击“新建 / 编辑”进入全屏编辑态，而不是普通弹窗
- 默认进入 `画布` 页签
- 画布支持平移、缩放、适配全貌与 `MiniMap`
- 阶段保持固定横向排布，节点可在阶段内自由拖动
- 顶部页签承载全局配置，右侧面板承载当前对象属性
- 存在未保存修改时，离开编辑态会给出确认
- 保存失败时，用户能看到中文错误摘要并定位到具体对象
- 现有新建、编辑、保存、删除、立即运行主流程不被破坏

## 10. 结论

本次改造的核心不是增加更多流程能力，而是把当前“能渲染流程图但几乎不可用”的编辑器，重构为一个可顺畅编排、可看清全貌、可定位错误、可稳定保存的专业工作区。

最终方案可概括为：

- 在 `workflows` 标签页内引入全屏编辑态
- 阶段固定横向排布，节点在阶段内自由拖动
- 顶部页签承载全局配置，右侧面板承载当前对象属性
- 保持后端接口和执行语义不变，优先完成前端可用性重建
